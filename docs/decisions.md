# Decisions

One line per decision: what was decided, and why. Newest at the bottom.

| Date | Decision | Why |
|---|---|---|
| 2026-11-16 | Stack: Next.js (App Router) + TypeScript + Tailwind, Supabase (Sydney, ap-southeast-2), Vercel, npm. | Set in CLAUDE.md. Sydney keeps data in Australia. |
| 2026-11-16 | Product name, tagline, support email and domain live only in `src/config/brand.ts`; a test fails if the name is typed anywhere else. | Name/trademark/domain checks are still open. |
| 2026-11-16 | Brand colours are defined once in `src/app/globals.css` (`pitch`, `lime`, `workon`). | One place to change the look. |
| 2026-11-16 | Age rules in `src/config/age-rules.ts`: under 13 = parent account only; 13–17 = parent may invite child to own login (parent still sees and can delete everything); 18+ = can sign up alone. | Owner's choice; kept in one file in case the lawyer wants a different line. |
| 2026-11-16 | Store a child's birth year, not full date of birth. Age is worked out using the younger possible age. | Collect only what is needed; never treat a child as older than they are. |
| 2026-11-16 | Public sign-up only for parents and adult players. Coach and admin roles can only be given by an admin. | Nobody can make themselves a coach. |
| 2026-11-16 | Video provider: Mux, **pending a data-terms check** (where video is stored, how it's used). No child's video goes to any provider until the owner approves. Only fake/sample video until then. | Mux has resumable phone uploads, clips cut from timestamps, and expiring signed playback links. |
| 2026-11-16 | Consent wording drafted in plain English by Claude; a lawyer checks it before launch. | Australia's Children's Online Privacy Code is coming. |
| 2026-11-16 | Pages ask search engines not to index the app. | Private app used by children. |
| 2026-11-16 | Tests use Vitest (`npm test`). | Simple, fast, works with TypeScript. |
| 2026-11-16 | Supabase settings (Project URL + publishable key) go straight into Vercel's Environment Variables; the owner never pastes keys into chat. The secret/service_role key is not used by the app yet. | Keeps keys out of chat and out of GitHub. The publishable key is safe to be public; row-level security protects the data. |
| 2026-11-16 | Home page shows a "Setup check" box that tests the Supabase connection on each visit, with a plain-English reason if it fails. | Lets the owner confirm setup without technical tools. |
| 2026-11-17 | Logo redrawn as SVG from the owner's 1080px PNG (original kept in `docs/brand/`). Logo symbol at `public/brand/logo-mark.svg`, path set in `brand.ts`; shown beside the name (name is text, read from `brand.ts`). Browser-tab icon `src/app/icon.svg`, phone home-screen icon `src/app/apple-icon.png`. | SVG stays sharp at any size with a transparent background; logo has no words, so the name stays in one place. |
| 2026-11-17 | Database changes are written as migration files in `supabase/migrations/` and tested on a local copy of Supabase (`npx supabase db reset`, then `npm run test:db`) before reaching the real database. | Real data is never used for testing; every change is repeatable. |
| 2026-11-17 | Logins (`profiles`) and footballers (`players`) are separate tables. Under-13s are a `players` row with no login. | Matches the age rules: young children never have their own account. |
| 2026-11-17 | Player stores first name, birth year and optional team only. Shirt number, shape and kit colour are stored per match (Week 2). | Collect only what's needed; shirt numbers change between matches. |
| 2026-11-17 | Every table has row-level security ON from creation, with no access rules until Step 4. A test checks no table is ever left unlocked. | Locked by default; nothing is exposed by mistake. |
| 2026-11-17 | Sign-up can only create a parent or a player; asking for coach/admin gives parent. | Nobody can make themselves staff. |
| 2026-11-17 | When the last guardian of a player with no login is removed, the player and their consent records are deleted automatically. | Deleting an account must really delete; nothing left with nobody responsible. Lawyer to confirm whether consent records must be kept for a period. |
| 2026-11-17 | Clubs are prepared for with `organisations` + `organisation_members` (one "Independent coaching" organisation at launch); coach access goes through `coach_assignments`. | Clubs and more coaches can be added later without a rebuild. |
| 2026-11-17 | Each login has one role for now. | Simple; can become several roles later if someone is e.g. both parent and coach. |
| 2026-11-17 | Admins manage accounts, roles and coach assignments but do NOT automatically see players' videos; an admin can be assigned as a coach (so the owner needs only one login). | CLAUDE.md: only the player, their parent and assigned coaches view a player's video. |
| 2026-11-17 | A coach can see an under-18 player only while assigned AND while a parent's consent is active. Withdrawing consent or ending the assignment removes access immediately. | Child safety comes before features. |
| 2026-11-17 | Not-logged-in visitors have no access to any table. Logged-in users can only edit specific columns (e.g. a parent can change a child's name but not attach a login). | Locked down by default. |
| 2026-11-17 | Only admins can change roles, enforced by a database trigger. | Nobody can promote themselves. |
| 2026-11-17 | Children and consents can't be created directly; Step 7 adds a checked function that does both together. | A child can never exist without the consent step. |
| 2026-11-17 | Teens (13–17) with their own login can see but not edit their own record; their parent edits it. Adults can edit their own. | Parent stays in control of a minor's data. |
| 2026-11-17 | The staff access log can't be edited or deleted by anyone through the app, including admins. Parents can read the log for their own child. | A trustworthy record; transparency for parents. |
| 2026-11-17 | Age numbers exist in both `src/config/age-rules.ts` and the database; a test fails if they ever differ. | Change in one place without the two drifting apart (change both, the test reminds you). |
| 2026-11-24 | Real Supabase is connected to GitHub: migrations in `supabase/migrations/` are applied automatically when they reach `main`. | No copying SQL by hand; the real database always matches the tested files. |
| 2026-11-24 | Sign-in settings in `supabase/config.toml`: email must be verified before logging in; passwords at least 10 characters with letters and numbers; changing a password needs a recent login. | Safe defaults for an app used by families. |
| 2026-11-24 | Steps 3–4 were applied to the real database by pasting `supabase/manual/week1-apply-once.sql` into the SQL Editor (the GitHub integration only made preview copies). Owner confirmed all 9 tables have row-level security ON. Future changes: set up an automatic GitHub Action before the next database change. | The free GitHub integration didn't deploy to production. |
| 2026-11-24 | Sign-up asks "Parent or guardian" or "Player aged 18+" and requires ticking "I am 18 or over". Under-18s can't sign up themselves; a parent adds them (Step 7). | Every self-made account is an adult; children come in only through a parent with consent. |
| 2026-11-24 | Email verification links come back to `/auth/callback`. If the link is opened in a different browser or app (common on phones), the email still counts as verified and the person is asked to log in. | Works reliably on phones without editing Supabase's email templates. |
| 2026-11-24 | Sign-up and "forgot password" show the same message whether or not the email already has an account. | Nobody can use the forms to find out who is a member. |
| 2026-11-24 | Links in emails can only send people to pages inside this site. | Stops a tampered link bouncing someone to another website. |
| 2026-11-24 | A browser test (`e2e/auth-flow.mjs`) checks the whole sign-in journey against a local Supabase, including the emails. | Proves it works end to end, not just piece by piece. |
| 2026-11-24 | Supabase's built-in email sender is used for now (only a few emails per hour). Switch to Resend before launch. | Fine for testing; not enough for real users. |
| 2026-11-24 | One `/dashboard` page shows a different home screen per role (parent: My children; player: My matches; coach: My players; admin: overview + accounts). Each screen just asks the database; the Step 4 rules decide what comes back. | The database, not the screen, is what keeps data private. |
| 2026-11-24 | The owner's account is made admin with a one-off SQL snippet (`supabase/manual/make-admin.sql`) in the Supabase SQL Editor. | Nobody can promote themselves through the app. |
| 2026-11-24 | Admin's account list shows names, roles and join dates, not email addresses, for now. | Emails live in Supabase's protected login table; showing them needs a database change, saved for when it's needed. |
| 2026-11-24 | A GitHub Action (`.github/workflows/database.yml`) updates the real database: it first runs every database check on a throwaway copy, and only if all pass does it apply new migrations. Secrets live in GitHub repository secrets, never in code or chat. | Automatic, and an untested change can never reach real data. |
| 2026-11-24 | The Action targets the real project explicitly (`--remote=<project ref>`); this Supabase CLI version targets a local database by default. | Prevents a job that silently updates nothing. |
| 2026-11-24 | A child is added through one database function (`add_child`) that saves the child, the parent link and the consent together or not at all. It checks: parent account, consent ticked, consent to the CURRENT wording version, child under 18 (and at least 3), at most 10 children per parent. | A child can never exist without consent, whatever the screens do. |
| 2026-11-24 | Consent wording lives in `src/config/consent.ts` (version `v1-draft`, for legal review). The database stores which version each parent agreed to; a test fails if the app's and the database's version differ. | When the lawyer changes the wording, you always know who agreed to what. |
| 2026-11-24 | Parents can withdraw consent (coaches lose access at once) and give it again; both records are kept. Parents can delete a child, which permanently removes the child, consents and coach links. | Parent stays in control; deleting really deletes. |
| 2026-11-24 | Teen (13–17) login invites split into Step 7c. | Needs a new server-only secret key in Vercel; better as its own small step. |
| 2026-11-25 | Teens (definitely 13–17, i.e. youngest possible age ≥ 13) can be invited by their own parent to their own login, only while consent is active. The database checks the request before any email is sent, and repeats every check when joining the new login to the child. | Under-13s never get a login; a child who might still be 12 waits. |
| 2026-11-25 | Invites are sent by the server using a separate secret key (`SUPABASE_SECRET_KEY`, Vercel only, marked Sensitive, never `NEXT_PUBLIC_`). The `server-only` guard makes the build fail if that code is ever used in a browser page; a check confirmed the key isn't in any browser file. | The secret key bypasses database rules, so it must never leave the server. |
| 2026-11-25 | A teen's own access needs active parental consent: withdrawing consent hides their record from them too. Removing a teen's login or deleting the child deletes that login. | The parent stays in control; deleting really deletes. |
| 2026-11-25 | An invite can't use the parent's own email or an email that already has an account. | Stops mix-ups and account take-over. |
| 2026-11-25 | The invite link signs the teen in from the page address, then removes it from the address bar straight away and asks them to choose a password. | Works with Supabase's default invite email; no template changes needed. |
| 2026-11-25 | Note: Supabase's built-in email sender allows only a few emails per hour (sign-ups, resets AND invites share it). Switch to Resend before real families use it. | Otherwise invites may fail at busy times. |
| 2026-11-25 | **Week 2 plan approved**: database, upload a match, tap yourself, coach review (clips, hand-placed ring, tags, notes, publish), player sees clips, delete really deletes. No AI, reports or sharing in Week 2. | Owner approval. |
| 2026-11-25 | Uploads: the parent uploads for under-13s; teens and adult players upload for themselves. The parent always sees everything. | Matches the age rules. |
| 2026-11-25 | New players are automatically assigned to the owner (the only coach at launch). | One coach for now; manual assignment comes with more coaches. |
| 2026-11-25 | Each match is uploaded as two videos, **first half and second half**, each up to 60 minutes. | Owner's choice. Covers 45 minutes plus stoppage time; smaller files upload more reliably from a phone. |
| 2026-11-25 | The full match video is deleted automatically 60 days after the coach publishes; clips are kept. | Lower cost and better privacy. |
| 2026-11-25 | Kit colour is free text (not a list). | Owner's choice: more accurate. |
| 2026-11-25 | Video provider check done (see `docs/video-provider-check.md`): neither Mux nor Cloudflare Stream stores video in Australia; Mux's terms let it use content to improve services and train its own AI on content without personal data or once anonymised. **Build with Mux's free plan and sample videos only; no real child's video until the owner and lawyer decide**, ideally with a written assurance from Mux. | Child safety rules: no children's footage to a provider until its data terms are checked and accepted. |
| 2026-11-25 | Week 2 database: `matches` (date, opponent, shape, free-text kit colour, shirt number, position, tap), `match_videos` (first + second half, max 60 min each), `clips` (2–60 s, hand-placed ring, strength + optional work-on note, draft/published), `clip_tags` (source ai/coach + which coach confirmed). Positions per shape live in `src/config/formations.ts`; a test keeps them matching the database. | CLAUDE.md requirements for upload, tap yourself, clips and tags. |
| 2026-11-25 | Players and parents only ever see PUBLISHED clips and COACH-CONFIRMED tags. AI-set tags are only visible to the coach until confirmed. Status changes (send to coach, publish) only happen through checked database functions. | "The AI never shows anything to a player. A coach approves first." |
| 2026-11-25 | Before any private playback link is handed out, the server calls `record_media_view`: it refuses anyone not allowed, refuses drafts to players/parents, and logs every staff view of a minor's video or clip. Admins get no automatic access to matches or videos. | "Log every staff access to a minor's video." |
| 2026-11-25 | Deleting a match, child or account queues every video and clip file in a private deletion list (`private.provider_deletions`); Step 6 deletes them at Mux. | "Deleting an account must really delete the files." |
| 2026-11-25 | A default coach setting (`app_settings`, admin-only) automatically assigns new players, and existing unassigned players when it's first set. | Owner is the only coach at launch. |
| 2026-11-25 | Adult players create their own player profile (birth year, team) the first time they upload. | Adults sign up without a child profile. |
| 2026-11-25 | Uploads go straight from the phone to Mux (Direct Uploads + UpChunk, 30 MB pieces, retries, pauses when offline and carries on). Our server only creates the one-time upload address, after the database checks the person may upload (`prepare_video_upload`). | Large files never pass through our server; dropped signal doesn't restart the upload. |
| 2026-11-25 | Mux settings: `playback_policies: ["signed"]` (private, never public), `video_quality: "basic"`, `max_resolution_tier: "1080p"`. If Mux ever returns no signed playback id, the video is treated as failed rather than using a public one. | Private by default; keeps costs down. |
| 2026-11-25 | Halves are checked for length on the phone before uploading and again after Mux processes them; anything over 60 minutes is deleted and marked failed. | Owner's two-halves rule, enforced even if the phone can't read the length. |
| 2026-11-25 | Video statuses are refreshed from Mux when the match page loads (no webhook needed yet). | Less setup for the owner; a webhook can come later. |
| 2026-11-25 | A pretend video service (`VIDEO_PROVIDER=fake`) is used for automatic tests; it refuses to run on Vercel. | Tests never touch Mux or need its keys. |
| 2026-11-25 | Fixed: the server account wasn't allowed to run the database's small check helpers (60-minute limit, valid position); a database test now covers this. | Found by the upload browser test before release. |
| 2026-11-25 | Still frames and (from Step 4) video playback use Mux signed links: a token signed with our Mux signing key (RS256), naming the video, the purpose and the moment, expiring after 10 minutes for frames. Built with Node's own crypto (no extra package); a test checks the signature. Keys `MUX_SIGNING_KEY_ID` / `MUX_SIGNING_PRIVATE_KEY` live in Vercel only. | Private by default; links stop working quickly if shared. |
| 2026-11-25 | Every frame request first calls `record_media_view` as the logged-in person: refused if not allowed, logged if it's staff viewing a minor. | Same check for every way of seeing a video. |
| 2026-11-25 | Tap yourself: choose the half, slide to a moment, tap on the frame (a lime ring marks it), save. A pitch diagram shows shape, position and shirt number. "Send to coach" needs the tap and at least one uploaded half; after that, videos and tap are locked. | CLAUDE.md "tap yourself" requirements. |
| 2026-11-25 | Admin home has "Make me the default coach"; coach and admin homes list "Matches to review" (only their assigned players, with consent). | Owner is the only coach at launch. |
| 2026-11-25 | Review screen (`/review/[id]`): the player's tap frame, pitch diagram, shirt and kit; the half plays in Mux Player via signed links (play, frames, timeline previews), each opening logged for minors. Coach marks start/end (2–60 s), places the ring by pausing and tapping, picks tags, writes a strength note (required) and an optional work-on note. Clips are drafts until Publish. | CLAUDE.md coach review requirements; nothing reaches the player before the coach approves. |
| 2026-11-25 | On Publish, each clip is cut at Mux as its own short private video (`mux://assets/…` with start/end), so clips survive after the full match video is deleted at 60 days. Failures retry on the next page load. | Clips are kept long-term; full videos are not. |
| 2026-11-25 | After publishing, the review is read-only for now. | Keeps v1 simple; editing published clips can come later. |
| 2026-11-25 | Fixed: editing a clip tried to change which half it belongs to, which the database (correctly) doesn't allow; technical database errors are now shown as plain English. Found by the coach review browser test. | |
